# TreeTalk for Obsidian

> 让 AI 对话成为一棵可以分支、回溯，并最终沉淀为 Markdown 知识的树。

TreeTalk 是一款桌面端 Obsidian 插件。它不把对话限制在线性聊天记录中，而是将每一次追问组织成可切换的树状节点，并允许你从任意问题、回答或笔记选段继续创建新的分支。

当一段对话真正有价值时，你可以把单条回答、指定节点或完整对话树沉淀为普通 Markdown 笔记，继续交给 Obsidian 管理、链接和长期保存。

## 当前版本

**0.9.0-alpha.21**

- 最低 Obsidian 版本：`1.13.0`
- 运行平台：桌面端
- 当前标准执行路径：`DeepSeek + Pi Agent + 完整上下文`
- 本版本仍处于 Alpha 阶段，建议升级前备份 Vault 和 TreeTalk 私有数据目录

---

## 从 0.8.21 到 0.9.0-alpha.21

这不是一次普通的小版本更新。自 0.8.21 以来，TreeTalk 的知识沉淀、笔记上下文、关系图谱和模型执行架构都完成了较大幅度的升级。

### 1. 知识沉淀回归纯 Markdown

TreeTalk 不再把沉淀笔记作为需要插件维护和回溯的私有档案。

现在：

- “沉淀回答”只生成标题和回答正文；
- “沉淀对话树”生成普通目录笔记和节点笔记；
- 不写入 TreeTalk 专用 YAML、来源 ID 或隐藏档案；
- 笔记可以自由编辑、移动、重命名和重新组织；
- 即使未来不再使用 TreeTalk，沉淀结果仍然是可直接阅读的 Markdown。

TreeTalk 负责帮助你从对话中获得知识，但不会接管你已经沉淀的笔记。

### 2. 新增沉淀关系图谱

完整对话树可以在独立关系图谱中查看和筛选。

图谱同时呈现：

- 对话父子节点；
- 当前笔记来源；
- 关联笔记；
- 正向内部链接和反向链接；
- 节点之间最终会写入 Markdown 的 WikiLink 关系。

你可以：

- 点击对话节点切换到对应分支；
- 点击笔记节点在 Obsidian 中打开原笔记；
- 拖动、缩放和平移图谱；
- 右键节点决定是否沉淀该节点；
- 右键连线决定是否保留对应知识链接；
- 为每个对话空间保留独立布局和视角。

关系图谱已经从早期 DOM/SVG 实现重写为 `PixiJS + Worker` 架构，并进一步加入共享内存、GPU 批量绘制、空间索引、按需渲染和中心向外的树状布局。输入文字和 AI 流式输出不会再反复重建图谱拓扑。

### 3. 笔记上下文升级为冻结关系图

从 Obsidian 笔记中框选内容提问时，TreeTalk 不只保存被选中的文字，还会在发送前冻结对应笔记正文和允许读取的关联关系。

当前支持：

- 当前笔记完整正文快照；
- 框选位置作为本轮重点；
- 沿内部链接读取关联笔记；
- 以同等规则读取正向链接和反向链接；
- 循环、汇合和重复文件自动去重；
- 关联深度控制；
- 发送前冻结并持久化。

原笔记之后被修改，不会反向改变已经发生的历史对话。旧回答始终对应当时真实使用过的笔记内容。

### 4. 引入 Pi Agent 渐进式上下文

0.9.0 系列加入了新的 Pi Agent 执行架构。

模型不再默认读取所有可能相关的内容，而是从当前问题最直接的上下文开始。当现有信息不足时，再通过统一的 `request_context` 接口按需请求：

- 当前章节；
- 当前来源的更多内容；
- 关联笔记章节；
- 关联笔记完整来源。

这种方式的目标是：

- 简单问题尽量快速完成；
- 复杂问题可以继续扩展证据；
- 关联笔记只是授权范围，不会因为开关开启就全部发送；
- 避免无关上下文稀释当前问题；
- 保持上下文来源、边界和使用过程可追踪。

当前硬限制为：

- 最多 50 次上下文扩展；
- 最多 51 次模型子请求；
- 最多新增约 30,000 Token 证据；
- DeepSeek 最终回答最多 16,384 Token。

### 5. 新增上下文发散模式

默认情况下，Pi Agent 优先围绕当前来源收敛地补充上下文。

开启“上下文发散”后，模型可以在现有权限范围内看到更多可请求的高层级来源，更适合：

- 多篇笔记综合分析；
- 主题横向比较；
- 从局部问题扩展到更广的知识范围。

该模式仍然受到关联笔记权限、冻结关系图、去重规则和 Token 上限约束。

### 6. 回答思考过程独立显示

支持思考的 DeepSeek 回答可以在生成期间显示独立、可折叠的思考面板。

思考文本：

- 只存在于当前运行内存；
- 不进入正式回答；
- 不写入对话 JSON；
- 不进入之后的模型上下文；
- 不进入搜索索引、关系图谱或沉淀笔记；
- 回答完成、失败、停止或插件关闭后立即清除。

alpha.21 进一步优化了思考流渲染：界面按消息局部更新，并合并高频增量，减少长思考过程中整个对话视图反复同步造成的卡顿。

### 7. 设置和输入区更加聚焦

为了降低配置复杂度，alpha.21 的正常使用界面已经收敛为：

- DeepSeek；
- Pi Agent；
- 完整对话上下文；
- 完整笔记正文；
- 思考开启或关闭。

输入区保留：

- 关联笔记；
- 上下文发散；
- 思考开关；
- 联网搜索；
- 发送与停止。

旧 Provider、Legacy 引擎、平衡上下文和压缩笔记模块仍保留在源码中，用于旧数据兼容和回归测试，但不再出现在 alpha.21 的标准新请求流程中。

## 核心功能

### 树状对话

- 每个标签页是一个独立对话空间；
- 当前节点可以继续对话，也可以创建子分支；
- 从任意历史节点切换和继续；
- 树状节点使用 AI 生成的简短提要，便于快速回溯；
- 根节点名称会同步到对话标签和历史记录。

### 框选追问

你可以框选：

- TreeTalk 中的用户问题；
- AI 回答；
- 普通文字；
- Markdown 标题、列表、表格和引用；
- 代码块、行内代码；
- LaTeX 公式；
- 当前 Obsidian 笔记中的内容。

选段会作为精确上下文加入草稿。TreeTalk 会尽可能保存对应的原始 Markdown、代码或 LaTeX，而不是只复制屏幕上渲染后的文本。

来自 TreeTalk 对话的选段会留下可点击高亮，并自动进入子分支模式；来自当前笔记的选段只补充上下文，不强制改变提问结构。

### 原生 Markdown 渲染

问题和回答使用 Obsidian Markdown 渲染能力，支持：

- 标题和列表；
- 表格；
- 代码块；
- 内部链接；
- 行内公式和块级公式；
- Obsidian Callout。

流式生成期间，未闭合的代码围栏、公式和表格会暂时保留源码显示，语法完整后再切换到正式渲染结果。

### 多会话与后台生成

- 同时打开多个独立对话空间；
- 切换标签页时后台回答继续生成；
- 生成状态按消息隔离，不会串到其他对话；
- 支持停止生成，并保留已经生成的内容；
- 支持历史对话搜索、打开、恢复和永久删除。

### 知识沉淀

- 沉淀单条完整回答；
- 沉淀完整对话树；
- 通过关系图谱选择节点和链接；
- 在原文附近保留框选追问对应的 WikiLink；
- 将选段直接拖入 Markdown 编辑器，生成普通引用块和返回来源链接。

## 安装

### 手动安装

下载发布包后，将以下三个文件复制到：

```text
<你的 Vault>/.obsidian/plugins/treetalk/
```

```text
main.js
manifest.json
styles.css
```

然后：

1. 重新加载 Obsidian；
2. 打开“设置 → 第三方插件”；
3. 启用 TreeTalk；
4. 打开“设置 → TreeTalk”；
5. 配置 DeepSeek API Key。

### 从 0.8.21 升级

建议先完整备份：

```text
<Vault>/.obsidian/treetalk-data/
```

升级步骤：

1. 关闭或暂时禁用 TreeTalk；
2. 用新版本覆盖插件目录中的 `main.js`、`manifest.json` 和 `styles.css`；
3. 不要删除 `.obsidian/treetalk-data/`；
4. 重新加载 Obsidian；
5. 重新启用 TreeTalk；
6. 检查 DeepSeek API Key 和当前功能开关。

现有对话仍沿用 `schemaVersion: 1`，关系图谱和冻结笔记关系也保留兼容协议。旧设置会在载入后迁移到 alpha.21 的标准执行路径。

## 基本操作

- 点击 TreeTalk 侧边栏图标：打开或关闭 TreeTalk；
- 点击“对话列表”：展开或收起当前打开的对话空间；
- 正常发送：继续当前节点；
- 在消息区或输入区空白位置单击右键：切换“继续当前节点 / 创建子分支”；
- 框选 TreeTalk 问题或回答：加入上下文并创建新的追问分支；
- 框选当前 Markdown 笔记：加入本轮上下文；
- 点击上下文条目右侧的 `×`：移除该项；
- 点击回答末尾的“沉淀回答”：生成普通 Markdown 回答笔记；
- 点击“沉淀对话树”：生成目录页和节点笔记；
- 打开关系图谱：筛选要沉淀的节点和链接；
- 点击生成中的停止按钮：终止当前请求并保留已有内容；
- 关闭活动对话空间：保存并归档。

## TreeTalk 摘录

将 TreeTalk 选段拖入 Markdown 编辑器后，会在准确落点插入：

```markdown
> [!quote] TreeTalk 摘录
> 被选中的原文
>
> [返回 TreeTalk 来源](obsidian://treetalk-open?...)
```

该引用块是普通 Markdown，可以继续复制、移动和编辑。

“返回 TreeTalk 来源”会尝试在当前活动对话和 TreeTalk 私有历史中定位原始消息。原对话被永久删除后，链接会提示来源不存在。

## 数据位置与隐私

活动对话和历史对话保存在：

```text
<Vault>/.obsidian/treetalk-data/
├── active/
└── history/
```

这些数据不会作为普通笔记显示在 Obsidian 文件列表、搜索结果或原生关系图谱中。

只有主动沉淀的回答、节点和对话树会成为普通 Markdown 文件。

默认沉淀目录：

- 单条回答：`TreeTalk 知识/`
- 对话树：`TreeTalk/`

API Key 使用 Obsidian SecretStorage 保存，不写入普通笔记。回答思考文本只存在于运行内存，不会被持久化。

## 命令面板

- `TreeTalk: 打开或关闭 TreeTalk`
- `TreeTalk: 新建对话空间`
- `TreeTalk: 关闭当前对话空间`
- `TreeTalk: 切换到下一个对话空间`
- `TreeTalk: 切换到上一个对话空间`
- `TreeTalk: 创建或关闭当前分支`
- `TreeTalk: 打开沉淀关系图谱`
- `TreeTalk: 打开历史对话`
- `TreeTalk: 恢复当前历史对话`

TreeTalk 不会覆盖 Obsidian 全局的 `Ctrl + W`。

---

## 当前限制

- 仅支持 Obsidian 桌面端；
- 当前版本仍为 Alpha，正式使用前请保留数据备份；
- 标准新请求流程固定为 DeepSeek 和 Pi Agent；
- 联网搜索依赖 DeepSeek 接口、账户权限和当前网络环境；
- 超大关系图谱的实际流畅度仍会受到设备 GPU、内存和 Obsidian 运行环境影响；
- 已经沉淀为 Markdown 的笔记由用户自行维护，TreeTalk 不会扫描、修复或反向同步这些文件。
