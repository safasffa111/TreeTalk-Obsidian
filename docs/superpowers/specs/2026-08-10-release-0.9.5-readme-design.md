# TreeTalk 0.9.5 发布与 README 更新设计

## 目标

将已验证的 TreeTalk 0.9.5 源码同步到正式 GitHub 仓库，并发布包含安装包的 0.9.5 版本。README 保留现有中英双语和完整操作说明，同时准确体现当前版本、产品定位与本轮稳定性优化。

## 发布范围

- 以本地已通过完整质量门的 0.9.5 源码为唯一同步来源。
- 排除 `node_modules`、本地备份、临时文件和其他非项目产物。
- 保留仓库的 Git 历史、远端配置和现有发布结构。
- 同步 `src`、`tests`、`regression`、构建配置、版本元数据、编译产物及其他正式项目文件。
- 使用现有 0.9.5 安装包作为 GitHub Release 附件，并核对其中包含 `main.js`、`manifest.json` 和 `styles.css`。

## README 设计

- 保留中文在前、英文在后的双语结构。
- 将当前版本统一为 0.9.5，删除过期的 0.9.0、0.9.2 和不准确的 Beta 版本描述。
- 首页定位强调“可追溯、可分叉、可沉淀的 Obsidian AI 研究工具”。
- 保留树状对话、精确选段、冻结上下文、渐进取证、关系图谱、WikiLink 与纯 Markdown 沉淀等核心能力说明。
- 新增 0.9.5 稳定性改进摘要：流式定向更新、自适应 Markdown 渲染、增量历史索引，以及最多四路且保持顺序的启动对话受控并发加载。
- 保留现有安装、操作、数据位置、网络隐私和故障恢复说明，不扩大尚未实现的功能承诺。

## GitHub 流程

1. 在 `agent/release-0.9.5` 分支同步并审查完整差异。
2. 执行 `npm run check`，要求测试、类型检查、代码规范检查、构建和回归测试全部通过。
3. 提交并推送分支，创建以 `main` 为目标的 PR。
4. 合并后创建 `0.9.5` 标签和 GitHub Release。
5. Release 附带正式安装包，并在说明中概括用户可感知的改进与验证结果。

## 验收标准

- `package.json`、`package-lock.json`、`manifest.json`、`versions.json` 的版本均为 0.9.5。
- README 中不再残留旧的当前版本描述。
- 完整质量门退出码为 0。
- GitHub 默认分支包含本次更新。
- `0.9.5` Release 可下载并安装，附件校验值与本地已验证安装包一致。
